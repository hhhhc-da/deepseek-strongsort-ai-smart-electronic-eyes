# i18n Guide

## Overview

- Locale config lives in `src/plugins/i18n/locale.ts`.
- Messages are split by feature in `src/plugins/i18n/locales/` and merged in `src/plugins/i18n/messages.ts`.
- Locale persistence uses `src/stores/locale.ts` (localStorage).

## Key naming

- `common.*`: global app labels and shared text.
- `nav.*`: sidebar, command menu, and navigation labels.
- `pages.*`: page titles/descriptions and page-specific UI strings.
- `errors.*`: error titles, descriptions, and actions.
- Feature modules follow their feature name (for example `marketing.*`).

## Usage in components

- Prefer `const { t } = useI18n()` and use keys in templates or computed data.
- For navigation data, store `titleKey` and translate at render time.

## Add a new language

1. Add locale entry in `SUPPORTED_LOCALES` in `src/plugins/i18n/locale.ts`.
2. Create new language folder under `src/plugins/i18n/locales/<lang>/`.
3. Add the same JSON module files as `en/` and `zh/`.
4. Import and merge in `src/plugins/i18n/messages.ts`.

## Common pitfalls

- Avoid hard-coded UI strings in templates when a key already exists.
- Keep keys stable; only update values when changing copy.
